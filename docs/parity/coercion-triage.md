# Value coercion and Lotus transition evaluation

## Confirmed causes

- **Transition arithmetic is a worksheet setting.** In public workbook `0f7ddb20-e7ec-43fa-a185-d2ed72cc7ef0.xlsx`, `Data!N445` is `=(1+(F445-U444)/U444)*100`. F445 is literal `n/a`, U444 is 22.36, and the cache is 0. The sheet has `sheetPr@transitionEvaluation="1"`. In `97542774-c5ab-416c-973e-793aaa388405.xlsx`, the flagged sheet's `I1000` is `=SUM(D1000:H1000)-F1000`: SUM already skips the `n/a`, but subtraction also needs to treat it as zero. The unflagged `Totals` sheet in `3021382e-04e6-4475-9bf4-437d6a544e0a.xlsx` inherits a flagged sheet's arithmetic through `SUM` and `ROUND`. Shared-formula expansion does not change those operands. A flagged sheet in `December.xlsx` also caches `=5174218+"october's actual kwh"/0.7457` as 5174218, demonstrating that the arithmetic rule applies to literal text, not just references. This agrees with [Excel's transition formula evaluation rules](https://documentation.help/MS-Office-Excel-2003/xlrefRulesUsedInCalculatingLotus123Formulas1.htm); ordinary worksheets must retain ordinary coercion.
- **Transition comparisons are distinct from ordinary comparisons.** In the public `SSCOTT8-22-00.xlsx` expense workbook, `Meals and Ent Sup!M10` is blank, L10 is 190.75, and `=IF(M10=" ",L10*1,L10*M10)` caches 190.75 on a flagged sheet. A flagged companion sheet evaluates `=IF(M2=0,"",'Short Form'!N3)` to empty text when M2 is a formula returning `""`. These cases do not imply that a space, the empty string, and a blank are interchangeable in ordinary sheets or in non-comparison contexts.
- **Unary plus does not perform numeric conversion.** The Excel-saved `MINUS_MINUS.xlsx` caches `=+TRUE` as Boolean and `=TYPE(+"3")` as 2. Other caches preserve referenced Booleans. In the public `Time.xls`, `Timesheet!A32` is a genuine blank and `=IF(+Timesheet!A32="","",+Timesheet!A32)` returns empty text with transition evaluation disabled. Preserving the intermediate blank does not change the rule that a scalar blank stored as a formula result becomes zero.

## Residuals and migration

- The selected public BIFF examples have 206 mismatched formula cells on transition-enabled sheets in four `.xls` workbooks. This is a count of affected sheets' discrepancies, not a claim that all 206 are caused by the flag. For example, `SCD-G1.XLS` caches `=K61+M61+I61` as 0 with three literal `--` operands, and `OPEC2.XLS` caches `=+F12+I12` as 70 with `-` and 70. The adapter cannot infer the setting from formulas or cache results. A future `craft-xls` API should expose `Sheet::transition_evaluation: bool`, default false, populated from `WsBool.fAltExprEval` ([MS-XLS §2.4.351](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/ccbd73f9-ff1d-4069-be31-13d16c074ec4)). The GridCraft adapter can then transfer it to the worksheet model and preserve it on XLSX export.
- Fifteen public query workbooks have manual calc and cache bare `Concat("C",$A$5:$A$100,"QueryPage")` as `#VALUE!`. The range holds row numbers, so these caches do not establish the behavior of modern [CONCAT](https://support.microsoft.com/en-us/office/concat-function-9b1a9a3f-94ff-41af-9736-694cbd6b4ca2), which accepts ranges. The absent future-function prefix, old formulas, and manual calc leave legacy function resolution or stale caches as plausible explanations. Dependent text-function discrepancies should not drive changes to `CONCAT`, `LEFT`, `LEN`, `TRIM`, or `&`.
